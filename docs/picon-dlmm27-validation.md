# Picon DLMM observed native swaps

The current sample contributes two previously missing positive Picon DLMM `swap_exact_in` sources, both direction X to Y, WSOL to USDC. Exact tuples are retained under `dex-swaps/fixtures/swap-coverage/picon-native27`, with all original PB bytes, finalized RPC transactions, raw/parsed owned pool/vault/bin-array evidence and a portable independent oracle. The oracle proves eight full ledgers: both users and both persistent vaults for each source. WSOL user close/recreation and SyncNative with the optional rent account are separately accounted for across the entire transaction.

The [official Picon organization](https://github.com/picon-finance) identifies the SDK as `@picon-finance/dlmm-sdk`. The retained official2.0.6 package IDL and generated PDA definitions identify the exact deployed program address, typed swap payload, ten principal roles, BinArray remaining-account group, Pool layout and SwapEvent. The package tarball SHA256 is `661fff4092d1c9c9fd4870da8ad9df964fe2db73f2e7f2a3bdca608ca50b32ba`. The owned upgradeable ProgramData deployment438802151 predates both originals; its ELF SHA256 is `f4cae378e19691f05ba629ba100d7454a10760a823b8a85ea1f730d994e3887b`. Raw Pool immutable mints/vaults match the native roles and its canonical pool PDA/bump; all three owned BinArrays bind the same pool and canonical bin-array PDAs. Native vaults are initialized classic-token ATAs of the pool.

The bounded decoder supports the canonical classic-token exact-in and exact-out layouts, one BinArray group with a positive declared count, two exact immediate committed checked transfers and one scoped97-byte SwapEvent. Exact-in requires the exact declared user debit and at least the minimum proceeds. Exact-out requires the exact requested output and input no greater than the declared cap. Native pool, side, debit, credit and zero transfer fees must agree with the scoped event. Both full persistent vault ledgers must agree with all committed token operations; wrong token programs or unsupported vault operations reject the receipt. Routed candidates pass the same strict helper. The physical input index identifies the source transfer.

Core tests include two finalized exact-in originals, two explicitly ABI-derived exact-out variants, four routed positives and148 native plus148 routed invalid variants. The derived exact-out variants are not additional finalized transactions. Token-2022 principal profiles and transfer-hook remaining groups have no independently proved finalized example here and remain excluded. This finite proof makes no universal coverage or historical reserve claim. Frozen metadata modules are unchanged.
