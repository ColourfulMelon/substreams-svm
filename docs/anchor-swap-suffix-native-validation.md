# Bounded Anchor swap suffixes

The finalized audit scope contains three Raydium CPMM `SwapBaseInput` calls with40-byte payloads and three Meteora DBC legacy `Swap` calls with32-byte payloads. The canonical typed prefix is24 bytes in both families. The retained suffixes are exactly16 and8 zero bytes respectively; unrelated discriminators, nonzero suffixes and other lengths remain excluded from this expansion.

Public evidence is retained in `dex-swaps/fixtures/swap-coverage/anchor-swap-zero-suffix`: all six complete original protobuf transactions and finalized RPC JSON responses, owned executable and ProgramData accounts, deployed ELFs/disassembly, DBC program-owned IDL, owned markets/mints, pinned official source files, and independent financial oracle. The portable oracle takes backend-package.json and protobufjs-package.json as two absolute arguments. It verifies complete key/signature/fee/gas/balance/instruction/runtime parity, all committed receipts, and24 full principal token ledgers, including native rent/WSOL lifecycle. No pricing tuple is taken from the candidate output.

Owned executable deploy slots452376460 (Raydium) and445503633 (DBC) predate the finalized originals. The verifier checks executable→ProgramData linkage and complete ELF byte/hash equality. Raydium entry discriminator comparison at `.text` indices62002–62004 reaches62198–62205 and the typed argument handler63651. DBC comparison141114–141116 reaches141421–141428 and144836. Those handlers remove the discriminator, require at least16 argument bytes (63660–63664 and144845–144849), then load only the first two u64 fields (63690–63693 and144875 onward). They do not require the suffix to be exhausted. This proves the retained padding is inert rather than introducing a new untyped swap operation.

The official source pins are `raydium-io/raydium-cp-swap@b3187ae53a1b95a201f855a59024a12ca8f5b51a` and `MeteoraAg/dynamic-bonding-curve@f552f20aa3c1c7631427c3827aeea7c58b902813`. The source and owned IDL bind the exact input/minimum and declared payer, pool, user accounts, vaults, mints and token programs. Current owned reserves are never used for historical pricing.

Raydium requires exactly two immediate committed checked Token transfers, user4→vault6 signed by payer0 and vault7→user5 signed by authority1, with declared mint10/11 and programs8/9. The input must equal the request and output meet its minimum.

DBC requires the two exact checked principal transfers followed by both authenticated self-CPI `EvtSwap` (170 bytes) and `EvtSwap2` (195 bytes). The event authority13, native program14, pool2, config1, direction, exact request/minimum, spent input, output and exact-input/no-remainder state are bound to the receipts. The optional referral is absent in this bounded expansion. The newer events are not emitted as duplicate price rows.

Both native expansion and routed candidate verification use the same settlement helper. Complete persistent vault token ledgers independently bind the receipt amounts even when the recipient WSOL account closes. Shared Token2022 net/minimum guards still apply. The independent retained Token2022 mint in these originals has metadata/pointer extensions and no transfer-fee configuration; its declared mint owner, complete transaction movements and absence of fee mutation are checked.
